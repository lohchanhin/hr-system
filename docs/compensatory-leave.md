# 調休存摺（國定假日適逢休息日的補假）

客戶 2026/10 的要求：「假設星期日國定假日，然後星期一就調休。員工可以選擇是否使用調休或保存起來，然後能看到自己保存的調休。如果要使用則發起簽核」。

1. 調休記錄：員工可以保存（決定要不要用），並且記錄來源。
2. 跑簽核確認使用調休。

## 重點規則

- **國定假日剛好是員工自己的休息日／例假時，員工得到一筆調休**（預設 8 小時），存進他的「調休存摺」，**預設保存**，不會自動放假。
  - 輪班人員：國定假日當天班表排「休」「例」，而且本月沒有另一個「國」對應這個假日（和國定假日休假紀錄的判斷相同）。
  - 行政人員：國定假日落在週六、週日或公司休息日（沒有班表時依公司行事曆）。
- **每一筆都記錄來源**，例如「2026-10-25 臺灣光復暨金門古寧頭大捷紀念日 適逢週日」「2026-10-10 國慶日 適逢例假」「人資手動給予：值班補償」「轉入既有補休時數」。
- 政府的補假日（例如 2026-10-26 星期一）**只是建議調休日**，不再是行政人員自動放假的日子（見下方「行為變更」）。
- 員工要用的時候，在簽核頁的申請表單選假別「**調休**」（「補休」「補假」也算）發起簽核：
  - **送出時檢查存摺**：申請時數超過「可用時數」（存摺剩餘 - 其他簽核中的調休）一律擋下（HTTP 400 `COMP_LEAVE_INSUFFICIENT`，訊息例如「調休餘額不足：存摺剩餘 8 小時（1 天）、其他簽核中的調休 8 小時（1 天），可用 0 小時（0 天），本次申請 4 小時（0.5 天）」）。和特休一樣不看假別的「超額處理」設定，沒有存摺（0 小時）的人也不能請。
  - **同時送出兩筆不會一起通過**：同一位員工的調休申請（新申請與退回後重新送出）在「檢查存摺 → 建立單據」之間一次只處理一筆（`compensatoryLeaveService.acquireCompLeaveFilingLease`，以 `CompensatoryLeaveState` 的 `key = filing:<員工 _id>` 唯一索引當作短暫鎖，用完即刪、程式中斷時 15 秒後失效；單機 MongoDB 沒有交易）。連點或兩個分頁同時送出時，第二筆等第一筆建立好才檢查，會把第一筆算進簽核中的時數而被擋下（400 `COMP_LEAVE_INSUFFICIENT`），不會兩筆都通過、合計超過存摺而之後都核准不了。等了 5 秒還拿不到鎖回 409 `COMP_LEAVE_FILING_BUSY`「另一筆調休申請正在送出，請稍後再試」。
  - **最後一關核准時再檢查一次**：送出之後存摺可能被人資扣除或被別張調休單用掉，不夠時不核准（HTTP 409 `COMP_LEAVE_INSUFFICIENT`），單據維持簽核中。
  - **核准時扣用存摺**：先到期的先扣（不設期限的排後面），再來是先取得的；可以跨好幾筆、每筆扣部分時數（例如 4 + 4 小時分兩次用同一筆）。
  - **整天的調休日具國定假日性質**：那一天對這位員工是假日（`holidayResolver` 的 `reason = compensation`、`via = comp_leave`），當天上班以國定假日出勤計（加班費日別）。「整天」是指請滿當天本來要上班的時數（排了 8 小時班請 8 小時；12 小時班要請 12 小時；行政人員沒有班表時是公司行事曆的上班日 8 小時）；只請幾小時的日子只是有薪的請假，不改變日別。
  - **否決、撤回（簽核中）**：還沒扣，簽核中的時數自然釋放。
  - **撤回已核准的調休**：申請人在假期開始前可以自己撤回，管理員任何時候都可以取消；系統返還這張單扣過的時數（只退確實扣過的，重複撤回不會重複返還），那一天也不再是假日。
- **薪資**：調休、補假是有薪假（`salaryConfig.LEAVE_TYPE_PAY_TABLE`），不扣薪。

## 額度的產生、作廢與提醒

額度由「國定假日休假紀錄」推算的觸發條件同步（`holidayCompensationService.syncHolidayCompensationsForLedger`），可以重複執行、不刪資料：

| 情況 | 處理 |
| --- | --- |
| 條件成立、還沒有額度 | 建立一筆未使用的調休（唯一鍵：員工 + 來源類型 + 國定假日日期，重複執行或兩個請求同時建立都只有一筆） |
| 還沒用過、條件不成立（例如班表把「例」改成上班、或排了「國」休到了） | 作廢（`void`，記錄原因），不刪除 |
| 作廢後條件又成立 | 重新開啟（人資作廢的除外，見下一列） |
| 管理員手動作廢（`voidReason = manual`，例如已改發加倍工資、不另給調休） | **同步不會重新開啟**（員工打開休假紀錄、人資重新計算、每日排程都一樣）；休假紀錄顯示「調休已作廢」，算已處理、不列入待處理 |
| 已經用過（部分或全部）、條件不成立 | **不自動收回**，標記「請人資確認」（`conflict`）；條件恢復時自動清除 |
| 已用掉的整天調休日之後被排成休息日／例假 | 同樣標記「請人資確認」（員工並沒有因此多休一天） |
| 國定假日從行事曆刪除 | 沒用過的作廢（`holiday_removed`），用過的標記確認 |
| 人資手動補登的國定假日調休 | 同步不動它 |

什麼時候同步：

- 查詢國定假日休假紀錄（排班頁「國定假日休假」）時，查詢的月份順便同步。
- 每日排程（伺服器啟動約 2 分鐘後，之後每天一次）：所有員工的上個月與本月；**行政人員另外同步本月之後到明年底、已建立公司行事曆的年度**（行政人員不必等班表，行事曆一建立就看得到之後的國定假日落在週末存入的調休）。
- 「國定假日休假 > 年度調休 > 重新計算」可以指定整年重算。

輪班人員的班表還是草稿、本月又還沒結束時，不建立也不作廢（等班表定案）。

## 員工、主管、人資看得到什麼

- **簽核頁「我的調休」**（每個人）：可用時數、存摺剩餘、簽核中、累計取得、已使用、已過期，以及每一筆調休的來源、時數（已用、剩餘）、狀態（未使用／部分使用／已使用／已過期／已失效）、建議調休日、使用紀錄（哪一張調休簽核、哪幾天、是否整天、核准狀態；HR 指定的日期與協商紀錄；人資扣除的原因）。
- **填請假單**：選「調休」並填時數後，欄位下方顯示「調休：目前可請 N 小時；本次申請 H 小時，核准後剩 M 小時」，超過時紅字說明無法送出。
- **我的假別餘額**：多一列「調休（存摺）」，額度欄顯示累計取得的時數，不分年度。
- **簽核人看單據明細**：申請人的各假別餘額下方附上申請人的調休存摺（調休單一定附上，其他請假單在申請人有調休時附上），核准後註明這張單扣了哪幾筆。
- **員工管理 > 薪資與特休 > 調休存摺**：取代以前人資手動填的「補休時數」。管理員可以**手動給予**（時數、取得日期、原因必填）、**扣除調整**（依扣用順序扣，原因必填）、**作廢**還沒用過的調休（原因必填）；已用過的不能作廢，請改用扣除或撤回簽核單。
- **國定假日休假紀錄**：國定假日落在休息日／例假的格子顯示「已存入調休」「已存入調休（已用 4 小時）」「調休已使用」「調休 10/26」（用在整天的調休）「補假 10/14」（HR 指定）；這些都算「補假／調休」、不算待處理。篩選「調休」列出有這類格子的員工；摘要多一個「已存入調休 N」。
  - **年度調休**（原「年度未排補假」）：依取得日的年度列出員工的調休（可篩選未使用／已使用／已過期／已失效／全部），另外提示「已使用但要確認」的件數。
  - **HR 指定**（只有管理員）：替還沒用過的調休指定日期（協商紀錄必填），會用掉這筆調休，指定的日子對這位員工具國定假日性質；可以改日期或取消（時數返還）。主管不再能排定。

## 行為變更（部署時請告知人資與員工）

- **行政人員不再自動放政府的補假日**。調休存摺上線（第一次啟動新版的**隔天**，記在系統狀態 `officeGovMakeupCutover`）之後的公務機關補假日只是「建議調休日」：國定假日落在週末改為存入調休，要放哪一天由員工發起調休簽核。
  - 上線之前的公務機關補假日照舊是行政人員的假日（已經放過的假、已經算過的薪資不變）。例如 2026-10-22 部署：10/9（補 10/10）照舊放假，10/26（補 10/25）變成一般上班日、10/25 存入一筆調休。
  - 排班頁標頭與班表匯出的「行事曆」列：上線後的公務機關補假日顯示兩行灰字「公務機關補假」（輪班人員僅供參考）與「建議調休日」（行政人員）；上線前的維持「公務機關補假」。
- **國定假日休假紀錄不再有「待排補假」**：存入調休就算已補償，不需要人資排日期；HR 指定改成管理員的動作。
- **補休不再是人資手填的數字**：員工資料的「補休時數」部署時轉入存摺（一次），之後改由存摺管理；假別規則的「補休」改名為「調休」（「補休」「補假」仍是它的別名），超過可用時數不能送出（以前是不檢查）。

## 假別規則（後台「請假與加班設定 → 假別額度與餘額規則」，存在 `leavePolicy`）

| 設定 | 預設 | 說明 |
| --- | --- | --- |
| `compensationHoursPerCredit` | 8 | 每筆調休的時數（1～24）；只影響之後新建立的額度 |
| `compensationExpiryMonths` | 0 | 期限（0 = 不設期限，最多 60 個月）。設定 N 個月時從取得日起算 N 個月（最後一天是 N 個月後的前一天），即時判斷，過期的剩餘時數顯示為「已過期」、不列入餘額 |

- 假別「調休」的名稱固定，別名一定包含「補休」「補休假」「補假」「調休假」（管理員可以再加），不能停用，超額處理固定是「不能送出」。後台畫面上調休那一列的額度顯示「依調休存摺（不分年度）」、計算期間「不分年度」，名稱、「超額禁止送出」（固定開啟）與「啟用」都不能改。
- 目前後台畫面還沒有這兩個欄位的輸入框，可用 `PUT /api/other-control-settings/leave-policy` 設定（驗證失敗回中文訊息）。

## 資料

新的集合 `compensatorycredits`（`CompensatoryCredit`）與 `compensatoryleavestates`（`CompensatoryLeaveState`，只有一筆系統狀態）。

- **為什麼另外開一個集合，不延用舊的補假義務（`holidaycompensations`）**：補假義務是「一個國定假日排一個補假日」（唯一索引：員工 + 國定假日），存摺的額度有時數、可以分好幾次用、也有不是國定假日的來源（人資手動給予、轉入的補休時數）；硬塞進舊集合要刪掉並重建唯一索引（單機 MongoDB 沒有交易，正式環境風險高），舊版程式也會讀不懂。另開集合，舊集合原封不動，**回復舊版程式時舊資料仍然可用**。
- 每一筆額度：員工、來源類型（`holiday_rest`／`manual`／`legacy_balance`）、唯一鍵 `sourceKey`（`holiday_rest:2026-10-25`、`manual:<id>`、`legacy_balance`）、原因（`rest_day`、`regular_rest`、`office_saturday`、`office_sunday`、`office_rest_day`、`manual_holiday`、`manual`、`legacy`）、國定假日日期與名稱、取得日、時數、已用時數、狀態（`available`／`used`／`void`；「已過期」即時判斷）、建議調休日、使用紀錄 `usages[]`（`leave_request`／`hr_assigned`／`adjustment`、扣了幾小時、哪張簽核單、各日時數、整天的日子、備註、誰、何時）、作廢原因、`conflict`。
- 沒有交易：每一筆額度各自用條件式原子更新扣用（剩餘時數夠才扣、同一張簽核單只扣一次），跨好幾筆額度時中途失敗就把這次已扣的退回再重試；返還只退「這張單確實扣過」的使用紀錄。
- 索引：`{ employee, sourceKey }`（唯一）、`{ employee, status, earnedDate }`、`{ employee, holidayDate }`、`{ employee, usages.fullDayDates }`、`{ usages.approvalRequest }`。

## 部署（伺服器啟動時自動執行，可重複執行，只記錄筆數）

1. 建立兩個新集合的索引。
2. 記下切換日 `officeGovMakeupCutover` = 第一次啟動新版的隔天（台灣時間；已經有就不改）。
3. **舊的補假義務轉入存摺**（只做一次，系統狀態 `compensationsMigratedAt`）：待排 → 未使用；已排定 → 已使用（使用紀錄是「HR 指定」、日期是原本的補假日，當天仍是假日）；失效 → 作廢。以「員工 + 國定假日」為唯一鍵 upsert，中途失敗重跑不會重複；舊集合不修改、不刪除。
   記錄：`Migrated N holiday compensations into compensatory leave credits (created C; open O, assigned A, void V); office government make-up days are suggestions from YYYY-MM-DD`
4. **員工資料的「補休時數」轉入存摺**（只做一次，系統狀態 `legacyHoursMigratedAt`）：大於 0 的員工各一筆「轉入既有補休時數」，員工資料的欄位不修改。
   記錄：`Moved compensatory hours of N employees into the compensatory leave bank (created C)`
5. 失敗只記錄錯誤名稱（`Failed to migrate compensatory leave bank`），不擋啟動；下次啟動會再試。

部署步驟不變：`git pull` → `npm ci` → 建置前端 → `pm2 restart`。部署後約 2 分鐘每日排程會同步本月與上個月（行政人員到明年底）的調休。

## 已知限制

- 員工批次匯入檔的「補休時數」欄位、員工 API 的 `annualLeave.compensatoryHours` 仍然可以寫入，但轉入存摺只做一次，之後的數字**不會**進存摺；請改用員工管理的「手動給予」。
- 公司統一挪移（`holidayMoveSettingController`）檢查「目標日不能是員工的補假日」、行事曆的對帳報告，仍讀舊的補假義務集合，還沒有改讀調休存摺的整天調休日。
- 已用過的調休條件消失時只標記「請人資確認」，標記不能手動清除（條件恢復時自動清除）；需要收回時請用「扣除調整」或撤回簽核單。
- 「國定假日休假紀錄」的格子不看期限（期限在調休存摺顯示）。
- 舊版的「登記處理方式：補休 N 小時」只是登記，不會產生調休；要給調休請到員工管理手動給予。
- 簽核單本身沒有另存「扣了多少調休」的欄位（扣用明細記在存摺的使用紀錄，單據上留一行紀錄「調休扣用」）。

## 對應的測試
