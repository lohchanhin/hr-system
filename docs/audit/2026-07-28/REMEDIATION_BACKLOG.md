# 分級修正待辦

稽核日期：2026-07-28
原則：本文件是後續修正方案；本次稽核未修改 API、Schema 或正式資料。

## 上線閘門

| 閘門 | 要求 |
| --- | --- |
| P0/P1 | 全部修正並通過回歸測試，或由業務、資安、法務及資料負責人書面接受風險 |
| 法規 | 每個計算規則記錄來源、生效日、公司政策版本及適用工時制度 |
| 資料 | Schema migration 具備備份、dry-run、驗證及回滾步驟 |
| 權限 | 員工、主管、管理員及專責角色完成正向與反向 API 測試 |
| 備份 | 在隔離環境完成可重複的 MongoDB 還原演練 |
| 測試 | 現有失敗分類清零或有核准基線；新增安全與法規測試全數通過 |

| 優先級 | 工作 | 負責角色 | 完成條件 |
| --- | --- | --- | --- |

| P0 | 對正式 MongoDB 建立一致性備份與 VM snapshot | DBA/維運 | 備份雜湊、集合/索引摘要及隔離還原成功 |

| P1 | 建立去識別化測試資料與正式資料不可用於開發的規則 | 資料負責人 | fixture 可覆蓋法規案例且無真實個資 |

## Phase 1：立即修正 P0

| 編號 | 工作 | API 行為變更 | 回歸測試 | 回滾方式 |
| --- | --- | --- | --- | --- |
| P0-01 | 簽核 actor 僅取自驗證身分；核對當前節點合法簽核人 | 忽略或拒絕 body `employee_id`；越權統一 `403/404` | 員工冒充主管、非當前簽核人、重複核准、併發核准 | 保留舊欄位只供相容讀取，不再參與授權 |
| P0-02 | 打卡對象綁定本人；人工補登使用獨立管理端點、權限與理由 | 一般員工傳入他人 ID 回 `403/404` | 他人打卡、跨部門補登、重複請求、時區與跨日 | 功能旗標只回退 UI，不回退授權檢查 |
| P0-03 | 所有班表寫入與刪除加入角色及物件範圍驗證 | 非負責範圍回 `403/404` | 主管刪除他部門、猜 ID、批次匯入與匯出 | 新授權 middleware 可逐路由啟用，但不得恢復公開刪除 |

P0 修正完成前，應視現有 JWT 為可能已被濫用：輪替 JWT secret、要求全部重新登入，並檢查最近簽核、打卡與班表異常紀錄。

## Phase 2：P1 權限、個資與交易完整性

| 工作 | 主要內容 | 驗收 |
| --- | --- | --- |

| 輸入與資源限制 | escape regex、欄位白名單、body/附件合理上限、查詢分頁 | NoSQL/regex/mass assignment/大型請求測試通過 |

## Phase 3：法規與資料模型

建議新增或重構以下版本化資料，而非把法規數值繼續寫死在 controller：

| 模型 | 必要欄位 | 用途 |
| --- | --- | --- |
| `WorkTimeRegime` / `PolicyVersion` | 組織、制度類型、適用職類、有效起訖、法定依據、同意/核准證據、公司限制 | 支援一般、二週、四週、八週制度及公司較嚴內規 |
| `WorkOccurrence` | 員工、實際起訖、時區、日別、來源、狀態、版本 | 統一排班、打卡、加班與結薪的實際發生時間 |
| `LeaveLedger` / `CompLeaveLedger` | 取得、使用、取消、到期、折薪、關聯簽核、冪等鍵 | 防止重複扣假並支援回補與結清 |
| `InsuranceRateVersion` | 制度、級距、費率、負擔比例、有效起訖、官方來源 | 依薪資月份選用當期勞保、就保、職災、勞退與健保版本 |
| `PayrollCalculation` | 期間、輸入快照、公式版本、逐項明細、四捨五入規則、狀態、重算關聯 | 避免新設定改寫舊薪資，支援重算與撤銷 |
| `Attachment` | owner、purpose、content hash、實際 MIME、大小、儲存鍵、保留期限、刪除狀態 | 私有存取、去重、掃描、保留與可證明刪除 |
| `AuditEvent` | actor、角色快照、物件、動作、request ID、時間、結果、hash chain/外部封存 | 追蹤敏感查閱及修改並降低竄改風險 |

資料遷移要求：

1. 先備份及隔離還原，再對副本執行 dry-run。
2. 新欄位先 nullable 或雙寫，完成回填與筆數/總額核對後再切讀取。
3. 舊班別文字映射到穩定代碼；無法判定的資料進人工覆核，不自行猜測「例/休」。
4. 舊簽核補上實際發生日期與計算版本；無證據者標記 `legacy_unverified`。
5. 薪資與保險遷移比較逐員工、逐月份總額，差異超過容許值即停止。
6. 回滾只切回舊讀取路徑，不刪除新資料；任何 destructive migration 另行核准。

| 領域 | 修正內容 | 關鍵測試 |

| 工時制度 | 依有效制度計算 8/40、二週、四週、八週及例休日 | 跨週、跨月、制度切換、無適用資格拒絕 |

| 加班費 | 平日、休息日、例假緊急、國定假日按區段與實際工資計算 | 逐分鐘邊界、四捨五入、跨日、重複結算 |

| 保險與勞退 | 匯入官方版本並由人工核准發布；舊月份鎖定舊版本 | 級距邊界、生效日前後、眷口、負擔比例 |

## Phase 5：依賴、設定與維運

1. 升級後端 `express`、`mongoose`、`multer`、JWT 鏈及其高風險傳遞依賴；逐項執行 API 回歸。
2. 處理前端 `lodash`、`lodash-es`、`postcss`；`xlsx` 無現成安全修補時，評估替代函式庫、隔離解析或限制可信輸入。
3. 將 JSON body 上限由 50 MB 降到業務所需，附件採串流、獨立限額及掃描。
4. MongoDB 啟用 authentication、最小權限角色、僅內網綁定及可行的 TLS；確認 `dbPath` 位於持久化磁碟。
5. 建立備份排程、保留世代、異地副本、磁碟與備份失敗告警；每季做隔離還原。
6. 增加安全標頭、request ID、結構化日誌、慢請求與敏感操作告警；正式日誌不得含 Token 或完整個資。

## 相容性與發布

- API 先新增明確的本人與管理範圍端點，舊端點回傳欄位逐步縮減並公告版本，不保留越權相容性。
- 寫入端以冪等鍵與版本號避免新舊客戶端重複執行；前端與後端同一發布批次切換 actor 行為。
- 法規規則先以 shadow mode 比對舊結果，記錄差異但不改正式薪資；經勞務確認後才成為阻擋規則。
- 每批發布具備資料核對腳本、功能旗標、監控指標及回滾決策人；不得以回滾為由恢復 P0 越權路徑。
