## 管理摘要

本轮以员工、主管、管理员三种角色，验证人资、组织部门、排班、打卡、签核、附件、薪资、保险、权限与错误边界，并对线上发现进行本地修复。测试未删除或覆盖既有业务文件与员工记录；所有主动建立的资料均使用固定标记并保留。另有一笔标记证明栏位因线上旧版“进入签核页面即自动修补表单”的缺陷，被附加到既有请假模板；该栏位未覆盖原栏位，已列入测试资料清单。

线上未发现可直接导致整库删除的 P0 漏洞，但发现 5 项 P1：打卡时间可由客户端控制且可重复、休/例班被薪资误算 24 小时、迟到早退扣款服务使用已移除栏位、恢复预设签核会删除既有模板关系、一般角色的员工选项资料过多。上述问题均已在本地代码修复并通过回归测试，必须重新部署后才会在线上生效。

修复后的工程准备度评估为 **8.1/10**；目前尚未更新的线上版本约为 **6.7/10**。这个评分不等同 ISO/IEC 27001、SOC 2 或法规认证。HTTP/TLS 依约排除，待正式网域与反向代理完成后另行验收。

## 线上发现与修复

### P1 高风险

| 编号 | 发现与证据 | 影响 | 修复状态 |
|---|---|---|---|
| P1-01 | 同一排班可重复上班打卡，且 API 接受客户端 `timestamp` | 可伪造或重复出勤，影响薪资与稽核 | 使用服务器时间；新增员工/排班/动作唯一键；重复回 `409`；下班前验证上班记录 |
| P1-02 | 5 个正常 D 班应为 40 小时，但两个 `00:00-00:00` 的休/例班各被算 24 小时，线上薪资显示 88 小时 | 薪资、加班、报表可能严重错误 | 薪资与报表统一 `休/例/OFF/REST` 分类，非工作班固定 0 小时 |
| P1-03 | 迟到早退服务查询旧的 `date/clockIn/clockOut`，现行记录实际为 `timestamp/action` | 扣款长期为 0 或与报表不一致 | 依现行 Schema 重写，加入宽限时间、跨日班及共用查询 context |
| P1-04 | `/api/approvals/restore-defaults` 会先删除全部模板、栏位、流程，再建立预设 | 历史签核关系可能断裂；失败时只完成部分删除 | 改为只建立缺少的 8 个模板，保留全部既有模板与历史申请；UI 改名“补齐预设值” |
| P1-05 | 非管理员员工选项 API 回传用户名、角色、签核标签、层级与组织资讯 | 超出业务需要的个资与权限资讯揭露 | 管理员保留完整设定资料；一般角色只返回 `id/name/displayName` |

### P2 中风险

| 编号 | 发现 | 修复状态 |
|---|---|---|
| P2-01 | 一般员工进入签核页面会主动调用建立/修补请假表单 API | 前端移除挂载写入；路由改为仅管理员 |
| P2-02 | 非签核参与者对已完成申请操作时先收到 `409 not pending`，可判断对象存在与状态 | 先验证参与者；非管理员越权统一返回 `404` |
| P2-03 | 主管关闭“包含自己”后，部分排班查询仍包含主管 | 所有相关请求明确发送 `includeSelf`，后端按排班视图过滤 |
| P2-04 | 签核附件对象显示为 `[object Object]` | 正确显示原始档名并通过受保护下载 API 读取 |
| P2-05 | 月底跨日班报表不读取次日退卡，休/例班可能被列为缺勤 | 出勤记录范围延长一天；早退与工时报表配对次日退卡；非工作班不计缺勤 |
| P2-06 | 劳保、健保、劳退使用过期或以百分比推算的级距 | 建立 2026-01-01 官方基准资料模组，附生效日与来源，启动时幂等补齐劳保级距 |
| P2-07 | 测试种子日志输出薪资金额及银行帐号 | 移除敏感明细，仅记录建立人数与笔数 |
| P2-08 | 打卡前端把分页响应物件误当阵列，导致有班表仍无法打卡 | 同时相容阵列与 `{ schedules }`，显示后端错误并避免按钮连点 |

## 已通过的业务测试

### 身分与权限

- 员工、主管、管理员登入与角色路由。
- 未登入请求返回 `401`；跨角色敏感端点返回 `403/404`。
- 登出 Token 撤销、JWT issuer/audience、帐号状态与权限版本检查。
- 登入限流、请求大小限制、CORS 与安全标头。
- 员工与主管无法读取薪资总览；管理员可读取及汇出。
- 非签核参与者无法读取受保护附件或代替他人签核。

### 排班与工时

- 每日超过 12 小时拒绝。
- 前后班间隔不足 11 小时拒绝。
- 连续 7 日出勤拒绝，且批次写入失败时不留下部分排班。
- `休` 与 `例` 班分类、跨周、跨月及跨日班退卡配对。
- 主管是否包含自己的筛选条件。
- 休/例班不进入应出勤、迟到、早退与薪资工时。

### 打卡

- 上班、下班、外出、返回与休息流程。
- 重复班次动作、未上班先下班、无当日排班、动作时窗外请求。
- 客户端无效时间拒绝；有效客户端时间不再成为实际打卡时间。
- 月排班响应格式与前端按钮状态。

### 签核与附件

- 送签、核准、驳回、退回、重送、取消及已完成申请的幂等保护。
- 缺少必填栏位、跨员工身分、非参与者对象授权。
- 证明文件 MIME、大小、档名与授权下载；直接猜 `/upload` 路径为 `404`。
- 恢复预设改为保留既有资料，仅补齐缺少模板。

### 薪资与保险

- 月薪计算、经常性津贴、请假、加班、夜班、迟到早退与汇出流程。
- 同一员工的班表、打卡与出勤设定只载入一次，降低薪资总览重复查询。
- 劳保 28 级、健保 58 级、劳退 62 级的边界与来源 metadata。
- 2026 最低工资与保险级距仅作为工程基准；正式结薪前仍须核对当期官方公告。

- 系统现有“每次迟到/早退固定金额”功能可能形成惩罚性预扣；劳动部说明工资不得预扣作为违约金或赔偿费用，迟到早退处理也应与工作规则一致。该功能预设关闭，启用前必须由台湾劳务/法务确认并改为可证明的比例计算或合法规则。[劳动部工资给付说明](https://www.mol.gov.tw/1607/28162/28166/28180/28194/29050/)、[劳动部迟到早退函释](https://laws.mol.gov.tw/FLAW/PrintFLAWDOC03.aspx?N2=4560&cnt=1&datatype=etype&lnabndn=1&now=1&recordno=1)

## 尚未关闭的风险

1. **管理员密码轮替（P1）**：线上测试管理员仍使用已知弱密码。部署后应立即从 UI 改为独一且高强度密码；不得再次写入脚本、截图或对话。
2. **备份与还原（P1）**：本轮未对正式 MongoDB 做破坏性还原演练。开放使用前必须先备份，并在隔离资料库核对 collection、文件数、索引与关键业务总计。
3. **迟到早退扣款政策（P1/P2）**：功能虽能正确计算次数，固定金额规则仍需劳务确认，未确认前保持关闭。
4. **保险历史版本（P2）**：目前提供 2026 基准及来源 metadata，但资料模型尚未保存多版本生效区间；跨年度重算仍需版本化。
5. **不可变稽核（P2）**：缺少对薪资、银行帐号、权限与敏感附件“读取行为”的 append-only audit event。
6. **特权 MFA 与职责分离（P2）**：管理员权限范围较广，尚未拆分系统、HR、薪资、考勤与稽核角色。
7. **PDF 字型（P2）**：目标机须安装繁中文字型并验证 PDF。
8. **前端包体（P3）**：主包偏大，低速网络首屏仍有优化空间。
9. **HTTP/TLS**：依本轮要求不评分；正式网域上线时必须补做 TLS、HSTS、精确 CORS、可信 proxy 与外部动态复测。

## 结论

本轮把最容易造成实际损失的资料完整性问题收敛：打卡不可重复或回填时间，休/例班不再扩大薪资工时，迟到早退使用正确资料模型，签核预设不再删除历史关系，一般角色取得的员工资讯也完成最小化。重新部署并完成密码、备份、字型三项闸门后，可进入受控试用；在变形工时、扣款政策与保险历史版本获得专业确认前，不建议宣称“法规完全自动合规”。
