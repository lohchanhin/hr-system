## 本轮完成内容

### 汇入与上传安全

- 员工与考勤汇入统一限制为 `.xlsx` / `.csv`，单档最大 5 MB。
- 前端选档时先检查副档名与大小；后端仍独立执行相同限制，不能只靠浏览器验证。
- 后端改用 Multer 2 的受控 memory storage，限制档案数、栏位数、parts、header pairs 与文字栏位大小。
- `.xlsx` 检查 ZIP 签名，`.csv` 使用严格 UTF-8/UTF-16 解码并拒绝异常控制字元；副档名、MIME 与内容不一致时回传 `400`。
- 超过档案限制时回传 `413`，缺档、重复档案与无法解析的 multipart 内容回传明确 `400`。
- 员工照片的 multipart 与 base64 两条路径都在解码前限制大小，并保留实际图片签名检查。
- 签核附件增加 multipart 结构限制，降低大量栏位或 parts 造成的资源耗尽风险。

### 依赖与前端资源

- Express、Mongoose、Multer、jsonwebtoken、Vite、Vue plugin、Vitest 与相关工具链升级至当前相容版本。
- 前端 SheetJS 改用官方 0.20.3 套件并随应用打包，不再运行时从第三方 CDN 注入脚本。
- ExcelJS 的旧 `uuid` 间接依赖以兼容的 11.1.1 覆盖；106 个 Excel 汇入、汇出与排班测试验证通过。
- 根目录移除重复且未使用的 Vite/esbuild/sass 工具，升级 PM2 与 concurrently，并覆盖 PM2 监看链的安全补丁版 `picomatch`。
- 前后端明确要求 Node.js `>=20.19.0`，与目标 VM 已显示的 Node 20.19.6 相容。
- 根工具链、前端与后端完整 `npm audit` 结果均为 0 个已知漏洞。

### 资料与排班可靠性

- Excel 日期以 UTC 组件解释，再依请求时区转换，避免服务器所在时区造成打卡日期偏移。
- 前后端时区工具固定使用 `h23` 小时制，并将部分 Node 20 / ICU 返回的午夜 `24:00` 正规化为 `00:00`，避免晚班被误算为 32 小时或前端显示 `24:xx`。
- 小于 5 MB 的工作簿改为完整读取首张 worksheet，消除串流 reader 在测试与小档案上的不稳定行为。
- 假日输入统一为 UTC date-only，拒绝不存在日期，并保留既有 `description/name/desc/type` 相容栏位。
- 种子资料的月份、请假工时、加班时段与签核主管 fallback 改为确定性逻辑，避免跨时区或随机资料造成不一致。
- 排班查询的签核资料暂时失败时保留上一笔成功资料，并显示重试讯息，不再把短暂失败误呈现为“没有请假”。
- 排班汇出不再发送空的 `department` 参数，避免后端把空值误当成筛选条件。

### 测试可靠性

- 修正固定写死月份、共享 mock 状态、非同步初始化、Windows 路径、Vite 测试 transform 与过期组件契约。
- 排班测试改以服务端分页、状态筛选、员工偏好及拆分组件的现行契约为准。
- Vite devtools 只在测试模式停用，不影响开发与生产行为。
- 夜班种子验证与安全授权整合测试改为显式环境开关，避免一般测试误连正式资料库。
- GitHub Actions 升级至 checkout/setup-node v4，并强制执行 `npm ci`、前后端全量测试、生产构建与三层依赖审计。

## 相容性说明

- 既有 API 路由与正常 `.xlsx` / `.csv` 汇入流程不变。
- UI 移除旧 `.xls` 选项。原后端采用 ExcelJS，本来就不支援旧 BIFF `.xls`；这项调整是移除误导性入口，并未移除可正常使用的汇入路径。旧档请另存为 `.xlsx` 或 `.csv`。
- 上传过大、格式伪装或 multipart 结构异常的请求现在会被拒绝，这是刻意的安全行为。
- 依赖升级后的最低 Node 版本为 20.19.0，部署时应使用 `npm ci` 依 lockfile 安装。
- 本轮未修改正式 VM、MongoDB 正式资料或 HTTP/TLS 配置。

## 部署前闸门

1. 先备份 MongoDB，并在隔离资料库成功还原后才更新应用。
2. 轮替管理员密码与 JWT secret，不使用仓库、截图或对话中出现过的凭证。
3. 前后端分别执行 `npm ci`；再执行前端 `npm run build` 与后端测试。
4. 同步部署前端与后端，避免分页、授权或 Token contract 版本不一致。
5. 部署后以员工、主管、管理员三种角色验证登入、员工资料、排班、请假、签核、打卡汇入、薪资与附件读取。
6. 检查 PM2 日志、MongoDB 日志、磁碟空间与慢请求日志，再决定开放给使用者。
