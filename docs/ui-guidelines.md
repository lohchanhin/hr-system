# 介面規範（2026/11）

目標：畫面簡潔、操作乾淨。使用者打開一頁，第一眼看到的是「要操作的東西」，不是裝飾與說明。
新畫面與修改既有畫面都照這份規範；共用樣式在 `client/src/assets/page.css`，共用頁首是 `client/src/components/PageHeader.vue`。

## 1. 頁首

- 每一頁最上面用 `<PageHeader title="…" subtitle="…">`：標題、最多一行說明。
- 統計數字放 `#stats`（`<span class="hr-stat"><span class="hr-stat__label">在職</span><strong class="hr-stat__value">8</strong></span>`）。
- 這一頁最主要的動作放 `#actions`（例如「新增員工」）。
- 不用漸層大橫幅、不重複標題（頁首有標題，下面的區塊就不要再寫一次同樣的字）。
- 只有一個頁籤時不顯示頁籤列。
- 頁首的版面只用 `PageHeader` 的選項調整，各頁不要再用 `:deep(.hr-page-header)` 改樣式：
  - `compact`：標題很短、要和統計或篩選排在同一列時（排班管理、出勤打卡）。
  - `stats-below`：統計數字固定排在標題與動作的下一列（薪資管理）。
  - `sticky`：設定很長、只有頁首一個「儲存」時，頁首固定在內容區頂端（出勤設定）。工具列要固定時用 `class="hr-toolbar hr-sticky-bar"`。
  - 固定的位置由外框設定的 `--hr-shell-padding`（桌機 24px、手機 12px）計算，各頁不要寫死 `top: -24px`。

## 2. 操作優先

- 表單與主要操作放最上面；參考資訊（餘額、規則說明、示意表格）放在旁邊或收合起來，預設不擋住操作。
- 欄位說明最多一行，用 `.hr-hint` 放在欄位下方。超過一行的說明收進「說明」按鈕、提示泡泡或可收合區塊。
- 不顯示沒有功能的設定與欄位（只存不用的設定不要出現在畫面上；資料保留）。
- 篩選條件與動作排成一列 `.hr-toolbar`（篩選在左、動作在右），不要每個按鈕各佔一行。

## 3. 按鈕

- 一個區塊最多一個主要按鈕（`type="primary"`），其餘用預設樣式。
- 破壞性操作（刪除、作廢、清空）用 `type="danger" plain`，按下後要二次確認，確認文字寫清楚會發生什麼。
- 文字用動詞且全站一致：新增、編輯、刪除、儲存、取消、查詢、匯出、匯入。不用「保存」「確定儲存」等其他說法。
- 送出中按鈕顯示 loading 並擋住重複送出。

## 4. 表格與清單

- 載入中顯示 loading；沒有資料時用一句話說明下一步（例如「尚未建立班別，請按右上角『新增班別』」）。
- 操作欄固定在右側；一列最多兩個常用操作，其餘收進「更多」。
- 日期時間格式全站一致：`YYYY/MM/DD`、`HH:mm`。

## 5. 回饋

- 儲存成功、失敗都要有訊息。失敗時顯示伺服器回傳的中文原因，不要只寫「操作失敗」。
- 表單驗證錯誤顯示在欄位旁，並捲動到第一個錯誤。
- 離開有未儲存變更的表單前要提醒。

## 6. 手機（寬度小於 768px）

- 員工會用手機的頁面（打卡、我的排班、簽核申請與簽核）必須單手可用：主要操作在第一屏、點擊區至少 44px、不出現橫向捲軸。
- 寬表格在手機改成卡片清單，或只留關鍵欄位；關鍵操作按鈕一定看得到。
- 對話框在手機用全螢幕或接近全寬，底部按鈕固定可見。對話框只寫桌機寬度（`width="520px"`），窄螢幕不超過螢幕寬度由共用樣式（page.css）處理，不要各自寫 `min(…, 100vw - …)`。
- 導覽列（後台側欄、前台底部分頁列）目前所在的頁面用同一個強調色：深色底用白色、淺色底用主色 `--el-color-primary`。

## 7. 樣式

- 顏色、間距、圓角一律用 `client/src/assets/base.css` 的 `--hr-*` 變數，不新增顏色。
- 區塊用 `.hr-section`（白底、細框、圓角 8px），不疊加陰影與漸層。
- 字級：頁標題 20px、區塊標題 16px、內文 14px、說明 12–13px。
- 畫面文字一律繁體中文。
