# 主管鏈、請假長度條件、略過重複簽核人、流程試算

客戶 2026/10/30 送來「20261030迦南體系簽核權限.xlsx」：每個機構一張表，每一塊是「申請人 → 第一位簽核人 → 第二位簽核人」，另外一行「*7日以上簽核權限」寫請 7 日以上的假時多簽的人（例如 員工-->護理長-->主任-->醫療副院長）。

以前的系統只能用「9 張請假單 + 部門限定表單」湊出來，而且員工要自己選「7日以上」那張單（評估時 165 張 7 日假送在一般假單上，全部只走了短的流程）。這一版加了四個**選用**的功能，一張請假單就能做到：

| 功能 | 在哪裡設定 | 沒有用到時 |
| --- | --- | --- |
| 簽核類型「主管鏈」：從直屬主管一路往上，每一級主管一關 | 簽核流程設定 → 申請類型 / 關卡 → 設定關卡 → 簽核類型 | 和以前一樣 |
| 關卡的「適用條件」：請假滿 N 小時（或 N 日）才需要這一關 | 同上，「適用條件」欄（只有請假表單） | 每張單都要每一關 |
| 略過重複的簽核人 | 主管鏈一律；其他關卡在「通用流程規則 → 略過重複的簽核人」 | 關閉 |
| 流程試算：選一位員工與請假長度，看實際會走哪些關卡、誰簽 | 簽核流程設定 → 流程試算 | — |

另外「員工管理」的「直屬主管」可以搜尋任何部門、任何機構的在職員工（以前只列同機構同部門的主管），主管鏈要用到別的機構的主任、總幹事、副院長。

**沒有用到這些新設定的表單、流程、已經送出的單據，行為和以前完全一樣**（預設的「申請者的主管 + 標籤 人資」、員工／標籤／角色關卡、無上級主管時的簽核人都沒有變）。

---

## 1. 簽核類型「主管鏈」

設定兩個值：

- **簽到持有此標籤的主管為止**（可不填）：例如「一般假單決行」。從直屬主管往上，簽到**第一位持有這個標籤的主管**（含這一位）就停。不填＝一路簽到最上層。
- **最多幾級主管**（1–10，預設 5）：最多幾位主管簽核。

### 怎麼走

1. 從申請人的**直屬主管**開始（員工管理的「直屬主管」），再看這位主管的直屬主管，一直往上。
2. 每一位主管是單據上的一關，名稱是「第1級主管」「第2級主管」…（流程關卡有寫「關卡說明」時是「說明（第n級主管）」）。必簽、需全員同意、允許退簽照這一關的設定。
3. 停止的時機（先到先停）：簽到持有停止標籤的主管、到最多層數、沒有更上層的直屬主管。
4. **申請人本人永遠不在鏈上**。主管資料繞回已經走過的人（例如兩位主管互為直屬主管）就停在那裡，單據說明「主管資料形成循環」。
5. **中途的主管已離職、帳號停用或留職停薪**：略過這個人，繼續找他的直屬主管；那一關的說明寫「已略過留職停薪的 OOO（第1級主管），改由上一級主管簽核」。
   - 略過的人剛好持有停止標籤（例如決行的主任留職停薪）：由上一級可簽核的主管**代為決行**，簽完就停，不會一路簽到最上層。
6. **一位主管都沒有**（沒有設定直屬主管、往上的人全部都不能簽）：
   - 必簽的主管鏈：和「申請者的主管」一樣改送**無上級主管時的簽核人**（見 [approval-department-forms-and-fallback.md](approval-department-forms-and-fallback.md) 的 R5；預設是系統管理員，任一位核准即可）。
   - 選填的主管鏈：這一關不放進單據，紀錄寫「第2關（主管鏈，到「長假決行」為止）沒有可簽核的主管（申請人尚未設定直屬主管），這一關略過」。
7. 已是前面關卡簽核人的主管一律略過（見第 3 節）。
8. 展開之後整張單最多 20 關；超過時送出會失敗：「【請假】的簽核流程展開主管鏈後共有 21 關，超過上限 20 關；請聯絡管理員調整關卡或「主管鏈」的最多層數」。

主管鏈和其他關卡一樣是**送出時（和退回後重新送出時）解析**：之後才改的直屬主管、標籤，只影響之後送出的單；簽核中的單據不變。

### 單據上看得到的

- 簽核頁、排班頁的單據明細：「第 2 關・第2級主管」，有略過離職主管時多一行說明。
- 「我已簽核」：決議後面附上「已核可（第3級主管）」。
- 簽核紀錄的新動作：「主管鏈」（略過離職主管、循環、沒有可簽核的主管）、「略過重複簽核人」、「關卡不適用」、「關卡照常簽核」（讀不到請假長度時）。

## 2. 關卡的「適用條件」（請假長度）

只有**表單性質＝請假**的表單有「適用條件」欄。選了條件的關卡，只有請假長度**大於或等於**設定值才需要（剛好 7 日也算）；不到的單據整關不送，紀錄寫「第2關不適用（請假未滿 56 小時，本次 52 小時）」。

| 條件 | 怎麼算 | 範例 |
| --- | --- | --- |
| 請假時數 ≥ N 小時 | 這張假單的請假時數（時數欄位；沒有填就依起訖時間推算，與特休扣抵、薪資相同） | 56 小時 |
| 請假日數（日曆日）≥ N 日 | 請假期間的台灣日曆日，含頭尾；有時分的請假碰到的日子都算一天；週末、國定假日也算 | 7 日 |
| 請假日數（排班日）≥ N 個排班日 | 請假期間**排了工作班**的日子；排休息日、例假、國定假日的日子不算；**沒有班表的日子以日曆日計算**（寧可多簽，不能讓該簽的關卡被跳過），紀錄說明「期間沒有班表，以日曆日計算」 | 7 個排班日 |

- 送出與退回後重新送出都會重新判斷：6.5 日的單被退回、改成 7 日重新送出，就會多出 7 日以上的關卡。
- 讀不到請假長度（例如表單性質後來被改成一般）：有條件的關卡**照常簽核**，紀錄寫「第2關照常簽核（無法判斷請假長度）」。
- 每一關都設條件時不能儲存：至少要有一關沒有條件，不然短假會沒有人簽核。
- 申請頁的流程預覽會在那一關下方寫「請假滿 56 小時才需要」（員工還沒填長度，預覽一律列出這一關）。

### 7 日要用哪一種算法（請客戶確認）

表上寫的是「7日以上」，系統三種都做得到，差別在輪班的人：

| 情況 | 56 小時 | 7 日曆日 | 7 排班日 |
| --- | --- | --- | --- |
| 行政人員請 11/16（一）–11/22（日），週末排休，5 個工作日 40 小時 | 不需要 | **需要**（期間有 7 個日曆日） | 不需要（5 個排班日） |
| 12 小時班的護理師請 5 個班（60 小時），期間 12 天 | **需要**（60 ≥ 56） | **需要**（12 日） | 不需要（5 個排班日） |
| 12 小時班的護理師請 7 個班（84 小時） | 需要 | 需要 | 需要 |

- **56 小時**：最接近「7 個 8 小時工作日」，但 12 小時班的人請不到 5 個班就達標。
- **7 日曆日**：最好懂，但連著週末請 5 天假就算 7 日。
- **7 排班日**：最貼近「請了 7 天班」，需要班表；還沒排班的期間以日曆日計算。
- 驗證時用的是「56 小時」（第 6 節的預期結果都是它）。客戶確認之後在「適用條件」改選即可，不需要改其他設定。

## 3. 略過重複的簽核人

- **主管鏈的每一級一律略過「已是前面任一關簽核人」的主管**（不只緊接的上一關）。例如第2關「主管鏈到長假決行」從員工往上走到護理長、主任、副院長，護理長和主任已經在第1關簽過，第2關只剩副院長（第3級主管）。
- 其他類型的關卡預設不變（和以前一樣，只有**連續而且簽核人、設定完全相同**的關卡會合併）。要讓它們也略過重複的人：「簽核流程設定 → 通用流程規則」選表單，打開「略過重複的簽核人」，按旁邊的「儲存」（這個開關會生效，和下面「尚未啟用」的規則分開存）。
- 一關的簽核人都已在前面簽過：這一關直接略過（不會因為「找不到簽核人」送不出去），紀錄寫「第2關（主管鏈，到「長假決行」為止）的簽核人都已是前面關卡的簽核人（OOO（第1級主管）、OOO（第2級主管）），這一關略過」；只有部分重複時只拿掉重複的人。

## 4. 員工管理的「直屬主管」

（編輯員工 →「任職資訊」分頁）

- 沒有輸入時和以前一樣，列出同機構同部門的主管。
- **輸入姓名或員工編號**就搜尋全部員工：同部門的主管排最前面，其次同部門、同機構，最後其他人；選項右邊顯示「機構／部門」。離職、留職停薪、帳號停用的人和本人不列出。
- 伺服器的規則沒有變：任何在職、帳號啟用的員工都可以當直屬主管（不限部門、機構）；不能是本人（「不能把自己設為直屬主管（會變成自己簽自己）」）；離職、停用的人不行。
- 兩位主管互為直屬主管（彼此簽對方的假）和以前一樣可以設定；主管鏈走到重複的人就停。
- 批次匯入不變。

## 5. 流程試算

「簽核流程設定 → 流程試算」（只有管理員）：

1. 選**表單**、**員工**；請假表單再填**請假日期**（同一天可以只填開始日期）與**請假時數**（不填＝依日期每天 8 小時，和送出時一樣）。
2. 按「試算」。畫面顯示：
   - 這位員工與他的直屬主管、請假時數／日曆日／排班日數；
   - **送出後的每一關與簽核人姓名**（第幾關、名稱、簽核人、來自設定的第幾關、必簽、說明）；
   - **每一關的判斷**：條件適不適用、主管鏈走到誰（哪幾級已在前面簽過被略過）、停在哪裡、無上級主管改送給誰；
   - **送出時會寫進簽核紀錄的內容**；
   - 實際送出會失敗時的原因（例如必簽的關卡找不到人），以及提醒（這位員工的部門沒有開放這張表單、表單已停用、員工已離職）。
3. 試算用的是和實際送出**同一份程式**（`services/approvalStepBuilder.js`），不會建立任何單據，也不會通知任何人。
   - 2026-11：**沒有「假別」欄位的請假表單**（客戶自建、只有日期與時數的表單）實際送出時也照日期、時數算請假長度，和試算一致。
     以前送出時讀不到假別就整個不看請假長度，有條件的關卡一律要簽，試算卻顯示不需要。表單上完全沒有日期、時數可讀時，有條件的關卡照常要簽（寧可多簽）。
   - 核准時的檢核：送簽之後才新增（或才改成必填）的**附件欄位**不追溯，加之前就在簽核中的假單照樣可以核准（以前回 400「請假申請必須附上相關證明」）。

建議設定好主管鏈之後，**每個部門挑一位員工、各試算一次短假與 7 日假**，和第 6 節的表對照。

- 特休、調休、事假、病假都是這一張請假單的假別，自動套用同一個流程。

以前為了湊流程建的「請假（7日以上）」等表單、部門的「使用簽核表單」限制，改用這張請假單之後可以停用（已送出的單據照常簽完）。

## 7. 技術說明（API 與資料）

### 流程關卡（`ApprovalWorkflow.steps`）

- `approver_type: 'manager_chain'`，`approver_value: { stopAtTag?: string, maxLevels: 1–10 }`（標籤和員工標籤一樣正規化：全形轉半形、去頭尾空白）。
- `condition: { kind, value }`（選用）：`leave_hours_gte`（0.5–2928，0.5 的倍數）、`leave_calendar_days_gte`、`leave_scheduled_days_gte`（1–366 的整數）。只有請假表單可以存（其他表單回 400「只有表單性質為「請假」的表單可以設定請假長度條件…」）；每一關都有條件時回 400。
- `policy.skipRepeatedApprovers: boolean`（預設 false）：`PUT /forms/:id/workflow` 只帶 `{ policy: { skipRepeatedApprovers } }` 時不動其他規則與關卡。

### 單據（`ApprovalRequest`）

- 關卡多 `name`（主管鏈的「第n級主管」）與 `note`（略過離職主管等說明），其他關卡、舊資料沒有這兩個欄位。
- 紀錄的新動作：`step_not_applicable`、`step_condition`、`skip_repeated_approver`、`manager_chain`（改送最高層簽核人仍是 `approver_fallback`）。
- `GET /api/approvals/history` 的 `my_approvals[]` 在有名稱的關卡多 `step_name`。

### 流程預覽 `GET /api/approvals/forms/:id/workflow`

和以前一樣以登入的人當申請人、只回人數與原因；用到新設定的關卡多：`condition_text`（「請假滿 56 小時才需要」）、`chain_levels: [{ level, label, repeated }]`（沒有姓名）、`repeated_count`、`skipped_as_repeat`。

### 流程試算 `GET /api/approvals/forms/:id/workflow/trial?employee=<員工 _id>&start=YYYY-MM-DD&end=YYYY-MM-DD&hours=56`（只有管理員）

回 `{ form, applicant, leave: { hours, calendarDays, scheduledDays, scheduledNote }, warnings, ok, error, steps: [{ step_order, name, source_position, chain_level, approvers: [{ id, name, employeeId, title }], fallback_text, note, … }], workflow: [每一關的判斷], logs }`。日期格式不對、結束早於開始、時數不合理回 400。

### 程式

`services/approverResolution.js`（`walkManagerChain`、`evaluateStepCondition`、主管鏈的無上級主管改送）、`services/approvalStepBuilder.js`（展開、條件、略過重複、合併、20 關上限；送出、重新送出、預覽、試算共用）、`controllers/approvalRequestController.js`（建立、重新送出時帶入請假長度；歷史的 `step_name`）、`controllers/approvalTemplateController.js`（驗證、預覽）、`controllers/approvalTrialController.js`（試算）；前端 `ApprovalFlowSetting.vue`、`Approval.vue`、`ApprovalDetailContent.vue`、`utils/approvalDetail.js`、`EmployeeManagement.vue`（直屬主管）。

## 8. 部署

不需要資料轉換：新的欄位沒有值＝和以前一樣（沒有條件、沒有主管鏈、`skipRepeatedApprovers` 關閉），啟動時也沒有要處理的資料。部署步驟不變：`git pull` → `npm ci` → 建置前端 → `pm2 restart`。

## 9. 已知限制

- 「員工管理」刪除員工前的影響提醒（失去持有者的標籤）、標籤清單的「被幾個流程使用」只看「標籤」關卡，不看主管鏈的停止標籤；刪除持有「一般假單決行」的人之前請先把標籤移給接任的人（不然主管鏈會往上簽到下一位持有者或最上層）。
- 排班日數用的是員工的班表（含尚未發布的草稿），沒有班表的日子以日曆日計算。
- 流程試算的員工選單顯示姓名與登入帳號、部門，不顯示員工編號（結果裡有員工編號）。
- 「最大簽核關卡數」等通用規則仍然只記錄、不生效；單據展開後的上限固定 20 關。
- 已經送出的單據不會因為改了主管、標籤、流程而重算；要套用新的流程，請申請人撤回後重新送出（被退回的單重新送出時會重算）。
