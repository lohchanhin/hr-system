# 班別代碼：休、例、國、請假的處理方式

公版班別表裡「休、例、國、事、特、補、原、病、公、公傷、婚、喪、生、檢、陪、產、家」都是沒有上下班時間（00:00–00:00）的班別。
系統用「**班別性質**」區分它們，整個系統（排班檢核、匯入、工時、出勤、打卡、加班費）都以這個性質為準。

## 班別性質

| 性質 | 代表 | 計工時 | 算例假 | 算休息日 | 中斷「連續 7 日」 |
| --- | --- | --- | --- | --- | --- |
| 工作班 `work` | 日、N、E、休D… | 是 | 否 | 否 | 否 |
| 休息日 `rest_day` | 休 | 否 | 否 | **是** | **是** |
| 例假 `regular_rest` | 例 | 否 | **是** | 否 | **是** |
| 國定假日 `holiday` | 國 | 否 | 否 | 否 | 否 |
| 請假 `leave` | 事、特、補、原、病、公、公傷、婚、喪、生、檢、陪、產、家 | 否 | 否 | 否 | 否 |

- 國定假日與請假**不能取代**例假或休息日（勞基法的例假、休息日與國定假日是不同類別），所以不計入每週的「1 例 1 休」，也不會中斷連續 7 日。
- 「沒有工作時間」（開始等於結束、且沒有勾跨日）的班別，不論性質為何，一律當成不用上班，不再被算成 24 小時。
  開始等於結束且勾了跨日才是 24 小時班。
- 跨日旗標只在「結束時間早於開始時間」時才有作用：N（00:00–08:00）即使勾了跨日也是 8 小時，不是 32 小時。

## 班別性質怎麼決定

後台「排班與班別管理設定」：

- 新增班別時，輸入代碼／名稱就會自動帶出建議的班別性質（休＝休息日、例＝例假、國＝國定假日、請假類＝請假，其餘＝工作班），也可以手動改。
  選了非工作性質會自動把時間設為 00:00–00:00、休息 0 分鐘，並鎖住時間欄位。
- 班別列表多一欄「班別性質」，「工作班卻沒有工作時間」會標記警告。
- 伺服器端的保護：新增或修改班別時，如果送來「工作班」但班別沒有工作時間，會自動改成對應的非工作性質，不會存下「沒有工作時間的工作班」。
- 伺服器每次啟動時會把舊資料修正一次（冪等，不會動有真實工作時間的班別）。**部署後請重啟一次伺服器。**

名稱判斷涵蓋公版的全部代碼：公傷／公傷假、婚／婚假、生／生理假、檢／產檢假、陪／陪產檢假、產／分娩假、家／家庭照顧假，以及原有的事、特、補、原、病、公、喪。
沒有工作時間、又不屬於休／例／國的班別，一律視為「請假」，不會當成工作班。

## 排班檢核（一例一休）

- **月底、月初的不完整週**：公司規定一週是週一至週日。一週跨出本次檢核的月份時，系統用資料庫裡**鄰月已存的班表**把這一週補齊
  （上個月、下個月兩個方向一樣，不分部門、不分草稿或已發布），再判斷一例一休。結果有三種：
  - 這一週的 7 天裡已經有 1 例和 1 休：通過，沒有任何提示。
  - 缺的例／休比「鄰月還沒排的日子」多（再怎麼補也補不齊）：**違規**。
    例如 10 月最後六天都排工作班、只剩 11/1 一天，一天放不下 1 例 + 1 休，就會報。
    訊息會多一段「此週跨月：…屬相鄰月份，…已排班／尚未排班」，說明哪幾天屬於相鄰月份、還剩幾天可以補。
  - 缺的例／休還補得上（鄰月還沒排完）：**目前無法判斷**，不算違規也不算通過。
    例如七月只匯入 7/1～7/5 都是日班，6/29、6/30 還沒排，系統會提示
    「跨月週（2026-06-29～2026-07-05）：2026-06-29～2026-06-30 尚未排班，暫時無法判斷每週一例一休（目前缺例假、休息日）；2026年6月 班表排定後會重新檢核」，
    每一項都指出是哪位員工、哪一週。
- **「目前無法判斷」不擋匯入、存檔、發布與完成發布**，只提醒：
  排班檢核按鈕的徽章在沒有違規時顯示待判斷的數量（藍灰色）；排班表上方的「尚無法判斷的跨月週」區塊逐位員工列出；
  匯入確認視窗另列「跨月週尚無法判斷一例一休」，同一週的員工合成一行；
  發布、完成發布的確認視窗註明另有 N 項跨月週無法判斷。API 的 `pendingWeeks` 只在有待判斷週別時才出現
  （`/api/schedules/rules/validate`、匯入預覽與匯入、發布、完成發布），`ok`／`count` 仍然只代表違規。
- **鄰月排定後自動重新判斷**：待判斷的狀態不另外儲存，每次匯入（預覽與匯入後）、排班檢核、發布、完成發布都用「當下」資料庫裡的鄰月班表重算，所以不會過期，也不需要資料轉換。
  匯入或儲存鄰月班表之後，鄰月那一邊的檢核會直接判斷同一週（違規或通過）；回到原本的月份時，切換月份會在背景重新檢核一次，徽章與提醒跟著更新。
  已完成發布（鎖定）的月份自己這一頁不再檢核，它的邊緣週改由鄰月那一頁判斷。
- 匯入檔的日期欄位不是整個月（例如只放了 28 天）時，整份檔案不檢核每週一例一休，預覽會明說「此檔案只有 N 天的日期欄位…未檢核每週一例一休」。
- **兼職人員不套用排班規範檢核**：員工資料「是否兼職」勾選的人，每週一例一休（含上述跨月週）、連續 7 日、每日工時（12／8 小時）、班與班間隔都不檢核，
  也不會出現在「目前無法判斷」清單裡。
  - 判斷在檢核服務的單一出口（`assertScheduleRuleCompliance`），所以預檢、匯入預覽與匯入、發布、完成發布一致。
    現場讀員工目前的兼職設定，不另存狀態：切換後整個月馬上依新設定檢核；沒有 `partTime` 欄位的舊資料算正職。
  - 仍然照常檢查：班別代碼對不到、員工代號重複、已核准請假日排上班班別、覆蓋與權限範圍等資料錯誤，以及請假、加班簽核的檢核與打卡限制。
  - 匯入預覽的確認視窗會說明「其中 N 位兼職人員不套用排班規範檢核」，排班表員工欄在姓名旁標示「兼職」。
  - 勞基法的例假、休息日與工時上限對部分工時勞工同樣適用，是否免檢核是公司的作法。
    上線前建議管理員先確認目前勾選「兼職」的名單（曾有新增員工帶照片時把「否」誤存成「是」的問題，誤勾的正職會被免檢核）：
    `db.employees.find({ partTime: true }, { employeeId: 1, name: 1, status: 1, department: 1 })`。
    部署只需要更新程式並重啟（沒有資料欄位或索引的變更，也不需要資料轉換）。
- 國與請假的格子不再觸發「每日工時超過 12 小時」「正常班超過 8 小時」「班與班間隔不足」。
- 真正的違規照常回報：連續 7 日沒有休／例、某週沒有例或沒有休、真實班別超時或間隔不足。

## 匯入班表

- 儲存格填「國」、請假代碼，或它們的名稱（國定假日、特休…），只要班別表有定義，就和「日」「休」一樣**存成班表的一格**，畫面、匯出、完整性檢查都看得到。
  班別表**沒有定義**的才略過，並提示「請到班別設定新增」。簡體的「国」「国定假日」也能對到「國」「國定假日」。
- 請假性質或國定假日性質的班別放在已核准請假日不算錯誤；工作班放在已核准請假日仍然是錯誤。
- 重新匯入並勾選覆蓋時，會取代這些日子既有的班表。
- 「國」可以排在當月任何一天（國定假日常常移休），匯入不再逐格比對「這天是不是國定假日」。只在兩種情況提醒（都只是提醒，不擋匯入）：
  「國」的數量超過本月國定假日天數（訊息含「假日日曆」）；以及檔案涵蓋整個月時，某位員工的國定假日當天上班、整個月卻沒有「國」可以對應（詳見下一節）。
- 預覽階段會直接跑排班檢核，確認視窗會列出提醒與違規的完整文字、國定假日／請假格數、不套用規範的兼職人員，以及尚無法判斷的跨月週；
  Excel 把代碼自動轉成日期（例如 11-20、08-12）時會還原後比對，找不到時錯誤訊息會顯示還原後的文字並提示把欄位格式設為「文字」。

## 假日資料

- 「一鍵載入當年國定假日」只儲存有名稱的假日；上游資料把每個週六日都標成假日（沒有名稱），這些不再存入。
- 伺服器啟動時會清掉舊版匯入留下的週末雜訊（來源為 roc-calendar、說明為空、落在週六日）。
  人工新增、沒有來源標記、平日、以及有名稱的假日（例如落在週六的國慶日）都不會動。
- 載入失敗時不再偷偷寫入內建的假資料（原本會把端午節寫成 6/10），而是顯示錯誤。
- 新增、修改、刪除、匯入假日只有管理員可以；一般登入者仍可讀取。
- 行事曆類型「例假日」「公司休息日」是公司自訂的休息紀錄，不算國定假日（排班標頭、排班檢核、加班費判斷一致）。

## 國定假日休假紀錄

回答「每月國定假日可能移休，有沒有機制記錄每個人的國定假日休在哪一天？沒休有沒有記錄？」：
排班頁工具列的「**國定假日休假**」會列出每位員工在每個國定假日的狀況。紀錄由班表**即時推算**，不另存一份，所以改班表（把「國」排到別天）立刻反映；只有「沒休之後怎麼處理」的人工決定才會存進資料庫。

**判斷方式**

- 每個月的國定假日來自假日行事曆（只算真正的國定假日，補班日、例假日、公司休息日不算），並套用「班別設定 > 國定假日挪移」的公司統一挪移（原日期與挪移後日期都會顯示）。
- 員工當月排了「國」的日期，依下列順序對應到假日：
  1. 假日當天就排了「國」：**當日休**。
  2. 公司挪移過的假日，員工仍把「國」留在原本的日期：**移休**。
  3. 其餘的「國」依日期先後，從最早的「國」對應到最早還沒對應的假日：**移休**，並顯示是哪一天、比假日早或晚幾天。
     當天本來要上班（或沒排班）的假日優先對應，假日剛好落在休息日、例假、請假的排後面，一個「國」不會被「本來就休息」的假日吃掉。
  4. 沒有「國」可對應的假日：**未休**，並記下假日當天的狀態（上班、未排班、適逢休息日／例假／請假）。
  5. 多出來、對應不到任何假日的「國」：列在「**多排的國**」（只是提示，不是錯誤，也不會自動算到下個月）。
- 「國」與假日是依序配對（班表上的「國」本身不記錄它屬於哪個假日），所以**總數（應休、當日休、移休、未休）一定正確**，個別配對的日期僅供參考。
- 到職前、離職後（員工狀態為離職才套用離職日；沒有離職日就看本月最後一筆班表）、留職停薪且本月沒有班表的假日標示「—」，不計入應休。到職、離職日以台灣日期判斷。
- 兼職人員和一般員工一樣有紀錄（畫面標示「兼職」）。離職、留職停薪或設定為不需要排班、而且本月沒有任何班表的人不列入（畫面會寫「另有 N 人未排班或不在職，未列入」）。

**狀態與待處理**

| 狀態 | 意思 |
| --- | --- |
| 當日休 | 假日當天排了「國」 |
| 移休 MM/DD | 假日當天沒休，MM/DD 排了「國」 |
| 未休·上班／未休·未排班 | 本月沒有對應的「國」，需要處理（待處理） |
| 適逢休息日／例假／請假 | 假日剛好是休息日、例假或已核准請假，僅供參考，**不列入待處理**（是否要補休由公司規定與 HR 判斷） |
| 尚未排國 | 本月還沒結束、班表還是草稿時，沒有「國」只是還沒排；排好之後自動變成移休，此時不開放登記處理方式 |
| 未休·補休 8 小時等 | 已登記處理方式 |

**沒休的處理方式**：對「待處理」的格子按「登記處理」，選擇補休（時數預設 8 小時）、折發工資、已另行補休（填實際補休日）、不補（備註必填）。
這裡**只登記，不會自動改薪資或員工的補休時數餘額**；以假日行事曆上的**原始日期**為鍵，所以公司事後再挪移假日，登記仍然對得上。同一位員工的同一個假日只會有一筆，可修改或刪除。
之後班表若補排了「國」，這個假日自動變成移休，登記保留但不再顯示。

**權限與匯出**

- 資料範圍和排班頁相同：管理員看全部，主管看自己與直屬部屬（預設不含自己，勾「包含自己」才含），員工只看得到自己（API：`GET /api/holiday-ledger?month=YYYY-MM`，也可用 `from`、`to` 查最多 12 個月）。
- 登記與刪除處理方式只有主管和管理員；主管只能處理直屬部屬，不能處理自己。
- 視窗可篩選未休、移休、待處理、多排的國，並匯出 Excel。班表「匯出 Excel」的第二個工作表「國定假日休假紀錄」也是同一份內容（第一個工作表仍是可匯入的班表格式；班表匯入只讀第一個工作表）。PDF 匯出不含這份紀錄。
- 班表 Excel 的「行事曆」列現在也會把公司挪移過的假日顯示在挪移後的日期，和排班畫面一致。

**部署**：新增資料集合 `holidayrestresolutions`（唯一索引：員工 + 假日原始日期）。伺服器啟動時會自動確認索引（冪等，失敗只記錄、不擋啟動），不需要手動遷移或回填；既有的班表、假日、挪移設定都不用改。
介面變更需要重新建置前端（`client/dist`）後重啟。

## 連帶影響（國、請假日一律視為「不用上班」）

- 排定工時為 0：不計入薪資用的出勤工時。
- 出勤報表：不算排班日、不算缺勤。
- 遲到早退：不扣。夜班津貼：不發。
- 打卡：休息日、國定假日、請假日不提供打卡視窗（例假沿用原本的訊息）；前一天的跨日班仍可在隔天凌晨簽退。
- 加班費日別：只以「算數的假日」判斷，補班日與舊週末雜訊不再被當成國定假日。

## 已知限制

- 排班表上手動新增班別（不是匯入）時，核准請假日仍會被擋下，包含國與請假類格子（匯入則允許）。
- 夜班津貼計算自己的跨日時數算法與其他地方略有不同（未勾跨日的夜班會提示設定問題），維持原本的提示行為。
- 客戶端的班別性質判斷是伺服器邏輯的鏡像（`client/src/utils/shiftSemantics.js`），修改伺服器的代碼清單時要一併修改。
- 國定假日剛好落在週六或週日時，格子只能填一個代碼；因為國不能取代例假與休息日，該週仍需有 1 例 1 休。
- 國定假日休假紀錄只呈現事實與人工登記的處理方式，不改變薪資：目前國定假日出勤只有核准的加班單會算加班費（以公司統一的有效日期判斷）；
  個別員工移休後，原假日當天上班是否算國定假日加班、是否合法的「調移」，須由公司與 HR 決定。
- 加班費日別（`buildCountedHolidayDays`）與排班檢核（連續 7 日）在來源假日已被刪除時仍會加入挪移後的日期，排班畫面與休假紀錄則不會；兩者在資料正常時一致。
- 日薪、時薪員工在「國」的日子目前沒有任何給薪（出勤工時只計算工作班）；這不屬於休假紀錄，需另案處理。
