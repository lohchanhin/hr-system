# 員工批量匯入

後台「人資管理 → 匯入員工資料」：上傳 `.xlsx` / `.csv`，一次建立或更新多位員工。

## 檔案格式

- 第 1 列：英文欄位名（如 `employeeId`、`name`、`email`）。
- 第 2 列：中文說明（只用來辨識，不匯入）。
- 第 3 列起：資料。
- 必填：員工編號、姓名、Email、身分證號（有設定預設登入密碼時身分證號可以不填）。
- 檔案裡**沒有必填欄位**時整批不匯入，錯誤寫出是哪一欄（例如「找不到必填欄位「Email」（檔案第 1 列要有「email」）」，`missingColumns` 列出 key／header／label）。
  **其他欄位**（範本的血型、學歷…被刪掉）檔案裡沒有也可以匯入，`warnings` 提醒「檔案沒有這些欄位，已略過」（以前任何一欄找不到整批都不能匯入）。
- 第 2 列是不是說明列：和以前一樣有 3 格與範本說明完全相同就是；另外，沒有 Email、數字這類資料、而且超過一半（至少 2 格）是範本的欄位名稱
  （只看括號前，例如「員工編號 (必填)」）也算。以前只留四個欄位、說明寫成「員工編號 (必填)」的檔案，說明列被當成第一筆資料。

### 後加欄位的備援讀法

特休與勞健保投保欄位若在第 1 列沒有英文欄位名，系統會改用第 2 列的中文名稱比對，不需要手動改表頭：

| 第 2 列中文名稱 | 對應欄位 |
| --- | --- |
| 年度特休總時數 | `annualLeave_totalHours` |
| 已使用時數 | `annualLeave_usedHours` |
| 年度特休總天數（舊版，仍可匯入） | `annualLeave_totalDays` |
| 已使用天數（舊版，仍可匯入） | `annualLeave_usedDays` |
| 積假 | `annualLeave_accumulatedLeave` |
| 請假期限 | `annualLeave_expiryDate` |
| 補休時數 | `annualLeave_compensatoryHours` |
| 勞保投保薪資 | `laborInsuredSalary` |
| 勞退投保薪資 | `pensionInsuredSalary` |
| 健保投保薪資 | `healthInsuredSalary` |
| 眷口數 | `dependentCount` |
| 簽核標籤（或「員工標籤」） | `signTags` |
| 簽核角色 | `signRole` |
| 簽核層級 | `signLevel` |

這些欄位都是選填：檔案裡沒有這些欄位也不會讓整批匯入失敗。
第 2 列的說明文字後面可以加括號備註（例如範本的「簽核標籤 (多個以逗號、頓號或分號分隔…)」），比對時只看括號前的名稱。

## 特休時數（單位是小時）

特休的單位是**小時**（1 天 = 8 小時）。範本的欄位是「年度特休總時數」「已使用時數」，請直接填小時數，例如 10 天特休填 `80`。

- 舊版檔案的「年度特休總天數」「已使用天數」仍可匯入，單位以「整份檔案」判斷：只要有任何一列的數字大於 40
  （法定特休最多 30 天，不可能是天數，例如 170、219），整份檔案都視為小時（客戶習慣把小時填在天數欄），並出現警告；
  整份檔案的數字都在 40 以內才視為天數，系統乘以 8 換成小時。建議改用新範本的「年度特休總時數」「已使用時數」欄位。
- **判定為小時的列**會在結果的 `warnings` 提醒是第幾列、填了什麼，請人資抽查；員工管理的編輯畫面也會顯示「由舊資料推斷為小時，請確認」，勾選確認後才算確認完成。
- 同一列同時填了時數欄位與舊的天數欄位時，以時數為準，舊的天數欄位忽略，並在 `warnings` 提醒。
- 空白儲存格不會洗掉員工原有的特休資料（更新模式）。

## 簽核標籤、簽核角色、簽核層級

簽核流程的「標籤／角色／層級」關卡是靠這三個欄位找簽核人的；匯入時沒填，這些員工就不會被派到任何簽核單，
需要「人資」「排班負責人」等標籤的表單會因為找不到簽核人而無法送出。範本已經包含這三欄。

- **簽核標籤**（`signTags`）：可填多個，用逗號（`,`／`，`）、頓號（`、`）、分號（`;`／`；`）或換行分隔，例如 `人資,排班負責人`。
  與員工表單、簽核流程使用同一套整理規則：全形轉半形、去掉前後空白、內部連續空白壓成一個空格、去掉空白項目並去除重複。
  單一標籤最多 50 個字、每位員工最多 50 個標籤；超過時該列的標籤欄位會被略過並提醒。
- **簽核角色**（`signRole`）：`R001`～`R007`，也可以填名稱：填報、覆核、審核、核定、知會、財務覆核、人資覆核（「覆核人員」這類舊寫法也認得）。
- **簽核層級**（`signLevel`）：`U001`～`U005`，也可以填 `L1`～`L5`。
- 角色或層級填了系統不認得的值時，**不會讓整批匯入失敗**：該欄位當作沒填，並在結果的 `warnings` 提醒是第幾列、填了什麼。
- 目前有哪些標籤、各有幾位在職員工持有、被幾個流程關卡使用，可在「人資管理 → 員工管理 → 編輯員工 → 簽核設定 → 員工標籤」的下拉選單查看。

## 人員狀態

- 除了 `正職員工／試用期員工／離職員工／留職停薪`，也認得常見寫法：正職、正式員工、在職（→ 正職員工）、試用、試用期（→ 試用期員工）、
  離職、已離職、離職中、辭職（→ 離職員工）、留停、停薪留職（→ 留職停薪）。
- **空白儲存格**：新增時使用預設的「正職員工」，更新時不動。
- **有填、但對不到上面任何一種**（例如「約聘」）：不會默默變成正職員工。該列會在 `warnings` 提醒「人員狀態無法辨識」，
  新增時仍以預設的「正職員工」建立（可以登入），更新時維持原狀態——請依提醒到員工資料手動調整。

## 資料格式的處理

- **CSV 檔每一格都當文字讀**：手機 `0912345678`、銀行代號 `004`、員工編號 `00123` 開頭的 0 不會不見（以前 CSV 會先被轉成數字）。
  數字、日期、是／否欄位再各自依欄位轉換，和 `.xlsx` 的文字儲存格相同。
- **性別**：`M`／`F`／`O`，也認得 `男`／`女`／`其他`（含「男性」「女性」與英文 male／female／other，不分大小寫）。
  空白＝沒填（新增時用預設值、更新時不動）；認不得的值只在 `warnings` 提醒、當作沒填，不會讓整批匯入失敗。
- **員工編號在同一份檔案內不可重複**（該列回報「員工編號重複」）；新增的員工帳號（預設＝員工編號）已被別人使用時回報
  「帳號「…」已被其他員工使用」，不會等到寫入時才出現資料庫的錯誤訊息。
- **同名的部門**（不同機構各有一個「護理部」）：依同一列的「所屬機構」決定是哪一個；機構沒填或對不上時該列回報
  「部門「護理部」在多個機構都有，請填寫正確的所屬機構，或改填部門代碼」。
- **日期**：除了 `yyyy-mm-dd`，也接受民國年（`091/12/01`、`60/10/1`、`115年9月1日`）。年份 3 位數以內視為民國年。
- **數字**：可含千分位逗號（`45,800`）。
- **積假**：`3國` 這類數字加備註的寫法，取前面的數字，並在結果提醒。
- **非數字文字**：投保薪資欄出現 `已勞退`、`投65歲` 之類的文字時，該欄略過（維持 0 或原值），並在結果提醒。
- **自提勞退**：範本標題是「自提勞退 (%)」，但系統的 `laborPensionSelf` 是每月扣款金額。
  填 0～1 之間的數字（`0.06` = 6%）時，會依勞退投保薪資（沒有則勞保投保薪資、薪資金額）換算成金額；
  找不到可換算的基準時略過，並在結果提醒。
- **主管員工 ID**：
  - 可填同一份檔案內的員工編號（主管本人也可以在同一次匯入）。
  - 填成自己的編號時不設定直屬主管（避免自己簽自己）。
  - 被其他人指定為主管、且匯入預設權限為「員工」的新建帳號，會自動設為 `supervisor`。
    **人員狀態是離職員工或留職停薪的人不會被自動升為主管**（他們不能登入，也不該取得主管權限），並在 `warnings` 提醒，請確認那些員工的直屬主管。

## 更新既有員工

匯入參數「更新已存在的員工資料」：

- **關閉（預設）**：員工編號或 Email 已存在就停止匯入，錯誤訊息會一次列出所有有問題的列（最多 20 列）。
- **開啟**：以員工編號比對（找不到才用 Email）：
  - 已存在 → 更新檔案裡「有填」的欄位。空白儲存格不會清掉原有資料。
  - 不存在 → 新增。
  - 簽核標籤／簽核角色／簽核層級**例外**：檔案裡有這個欄位時以檔案為準，填了就「取代」原有的設定（標籤是整組取代，不是合併），
    欄位存在但儲存格空白就是「清空」，並在 `warnings` 列出原本被清掉的標籤／角色／層級；檔案裡完全沒有這個欄位則不會動。
    不論是用員工編號比對到、還是員工編號對不到而退回用 Email 比對到的既有員工，都會有這個清空提醒
    （Email 比對到的員工，原有的聯絡人與薪資項目也一樣會帶出來合併，不會被當成沒有）。
    角色或層級填了不認得的值時，也不會拿來清空原有的設定。
  - 不會更動：帳號（username）、權限（role）、Email、密碼、員工編號。
  - 「其他薪資項目」有填時取代項目清單，**仍在清單裡的項目金額不動**（新加的項目金額是 0，請到員工資料補上）；
    緊急聯絡人只填了部分欄位（例如只有電話1）時，其餘欄位維持原值。
  - 不能把**最後一位可登入的管理員**改成離職／留職停薪（該列回報錯誤、整批不匯入）。
  - 被填為「主管員工 ID」的那一列如果是用 Email 比對到既有員工（檔案裡是新的員工編號），直屬主管會指向那位既有員工。
  - Email 已被另一位員工使用時停止匯入。
  - 先寫入新增、再更新；有交易支援時全部成功才提交，失敗會回滾並回報失敗列號。

## 結果

回應包含 `createdCount`、`updatedCount`、`preview`（每筆有 `action`: `created` / `updated`，`department` 是部門 `_id`、`departmentName` 是部門名稱），
以及 `warnings`（自動調整或略過的資料，匯入完成後請抽查）。

- 初始密碼規則看 `credentialRule`（預設是身分證號，或管理員設定的預設登入密碼）。`preview` **不帶**初始密碼：以前每一列都把身分證號以明碼放在回應裡，畫面並沒有使用。
- 資料庫是單機模式（正式環境）時，匯入成功不再附「資料庫為單機模式、不支援交易…」的提醒；寫入失敗時的訊息仍會說明環境不支援交易、已補償刪除新增的員工。

## 大檔案

新增的員工要各算一次初始密碼的雜湊（PBKDF2 十萬次）。這一步在背景執行緒分批計算，匯入期間其他人的操作不會被卡住
（以前 300 位新員工會讓整個伺服器停頓十幾秒）。筆數很多時整個請求仍需要一段時間（測試機 1,500 位約 28 秒），
前面有反向代理（nginx）時請留意逾時設定，或把檔案分成幾份匯入。

## 員工編號唯一（2026-11）

- 新增、修改員工（含批量匯入）時，非空白的員工編號不能和別的員工相同（API 先檢查，回中文錯誤）。
- 伺服器啟動時（`server/src/services/employeeNoUniqueness.js`）先計算目前有幾個員工編號被兩位以上的員工使用，只記錄筆數：
  `Employee numbers used by more than one employee: N numbers, M employees; unique index not created …`，不修改資料、不會讓啟動失敗。
- 沒有重複時建立唯一索引 `employeeId_unique_nonblank`（只看非空字串，沒有編號或空白的舊資料不受限制；建好之後啟動不再動它）。
  有重複時不建立：請在員工管理把重複的編號改好，下次啟動會自動建立。原本的一般索引 `employeeId_1` 不動。
- 索引建好之後，兩個請求同時用同一個編號新增（或修改）員工，後到的回 400 `{ error: '員工編號已被其他員工使用，請改用別的員工編號', code: 'DUPLICATE_EMPLOYEE', field: 'employeeId' }`
  （帳號、Email 重複同樣是中文訊息與 `field`），以前回資料庫的 E11000 原文。
