# 考勤資料匯入格式說明

後台管理者可透過「考勤資料匯入」功能匯入多筆打卡紀錄。此功能支援 Excel (XLSX) 與 CSV 檔案，並提供欄位對應、員工映射與預覽匯入流程。

## 基本欄位

匯入檔案需至少包含下列欄位，可於匯入介面調整欄位對應：

| 欄位 | 說明 |
| ---- | ---- |
| `USERID` | 打卡資料來源的員工識別值，可對應員工編號 (`employeeId`)、Email 或資料庫 `_id`。 |
| `CHECKTIME` | 打卡時間。支援 `yyyy-MM-dd HH:mm:ss`、`yyyy/MM/dd HH:mm`、`MM/dd/yyyy HH:mm` 等常見格式，以及 Excel 日期欄位。亦接受 12 小時制（例如 `2024-01-05 06:30 PM`）與含中文 `上午`/`下午` 標記（例如 `2024/01/05 下午 06:30:00`），系統會自動換算為 24 小時制。 |
| `CHECKTYPE` | 打卡動作，系統會將 `I` 轉換為 `clockIn`、`O` 轉換為 `clockOut`。亦支援直接填寫 `clockIn` / `clockOut`，或中文的 `上班簽到` / `下班簽退`、`加班簽到` / `加班簽退`（打卡機不區分平日與加班，一律視為一般上下班簽到退；加班費另由簽核單申請計算）。 |
| `REMARK` (選填) | 額外備註內容，將原樣寫入資料庫。 |
| `NAME` (選填) | 員工姓名，配合 `USERID` 使用可提高員工匹配準確度。 |

### CHECKTIME 的寫法（2026-11 複查後）

沒有時區資訊的時間一律當成匯入時區（預設台灣）的時間，結果不受伺服器本身的時區影響。

| 寫法 | 例子 |
| ---- | ---- |
| 西元年月日＋時間（24 小時制，秒與小數秒可省略） | `2026-11-10 08:00:00`、`2026/11/10 08:00`、`2026-11-10T08:00:00.000`、`2026.11.10 08:00`、`2026年11月10日 08:00` |
| 12 小時制 | `2026/11/10 下午 05:30:00`、`2026-11-10 05:30 PM`、`11/10/2026 05:30 PM` |
| 民國年 | `115/11/10 08:00`、`115.11.10 08:00`、`民國115年11月10日 08:00` |
| 緊湊格式 | `20261110083000`、`202611100830` |
| 美式月/日/年 | `11/10/2026 08:00` |
| Excel 的日期時間儲存格、Excel 序號 | 儲存格格式是日期時間就可以，不必先改成文字 |
| 帶時區 | `2026-11-10T00:00:00Z`、`2026-11-10T08:00:00+08:00`（依時區換算） |

- 只有日期、沒有時間（`2026/11/10`）當成當天 00:00。
- 月、日、時、分、秒超出範圍（2/30、13 月、24:00、25/12/2026）列為這一列的錯誤（`打卡時間的日期或時間超出範圍：「2026-02-30 08:00」`），不會自動進位成另一天。
- 已經是 24 小時制又帶「下午」（`下午 17:30`）照 17:30 計。

修正前的問題（都重現過）：Excel 的日期時間儲存格每一列都回「CHECKTIME 格式不支援」；帶毫秒或只有日期的寫法在台灣時區的主機上差了 8 小時（或變成前一天）；
超出範圍的值被悄悄存成另一天；民國年與緊湊格式不支援。測試：`server/tests/attendanceImportFormats.test.js`。

## 新格式支援

系統支援新的考勤機匯出格式，包含以下欄位：

| 中文欄位名稱 | 說明 | 對應欄位 |
| ---- | ---- | ---- |
| 部門 | 部門名稱 | (選填) |
| 姓名 | 員工姓名 | `NAME` |
| 差勤號碼 | 考勤系統編號 | (選填) |
| 日期時間 | 打卡日期時間 | `CHECKTIME` |
| 簽到/退 | 打卡類型（上班簽到/下班簽退） | `CHECKTYPE` |
| 機器號 | 打卡機編號 | (選填) |
| 編號 | 員工證件編號/員工編號 | `USERID` |
| 比對方式 | 識別方式（指紋/人臉等） | (選填) |

### 新格式範例

```
部門	姓名	差勤號碼	日期時間	簽到/退	機器號	編號	比對方式
迦美	楊世任	23	2025/11/1 上午 07:54:21	上班簽到	104	D0021	指紋
迦美	楊世任	23	2025/11/1 下午 12:00:03	下班簽退	104	D0021	指紋
迦美	楊世任	23	2025/11/3 上午 07:57:34	上班簽到	104	D0021	指紋
迦美	楊世任	23	2025/11/3 下午 05:01:47	下班簽退	104	D0021	指紋
```

使用新格式時，請在匯入介面設定欄位對應：
- `USERID` 欄位 → `編號`
- `NAME` 欄位 → `姓名`
- `CHECKTIME` 欄位 → `日期時間`
- `CHECKTYPE` 欄位 → `簽到/退`

## CSV 檔案的讀取

- 編碼：UTF-8（有沒有 BOM 都可以）、UTF-16LE / UTF-16BE（需有 BOM）、**Big5（ANSI）**：沒有 BOM、內容又不是有效的 UTF-8 時當成 Big5 讀
  （台灣的考勤機與 Excel「另存 CSV」常見的編碼；以前上傳時就被擋下「匯入檔案內容與宣告格式不一致」）。
  上傳檢查（`middleware/upload.js` 的 `createUploadMiddleware({ allowBig5Csv: true })`）只對考勤匯入放行 Big5，其他匯入照舊。換行 `\r\n`、`\n`、單獨的 `\r` 都可以，檔案最後的換行不會多出空白列。
- 欄位以逗號分隔；標題列沒有逗號、卻有 Tab 時改用 Tab 分隔（考勤機匯出的文字檔）。含逗號的值用雙引號括起來（`"早班, 支援"`），引號內的雙引號寫兩次（`""`）；引號內不支援換行。
- 整個檔案先讀成文字再逐行處理，筆數多的檔案（例如 5000 筆）也能預覽、匯入。
  原本用 Node 的 readline 逐行讀，在 Node 24 上超過約 1024 行的 CSV 會讀到一半失敗（回 400「無法讀取匯入檔案」，錯誤為 `readline was closed`）；
  測試：`server/tests/attendanceImportLargeCsv.test.js`（5000 筆，含 UTF-8 BOM + CRLF、UTF-16LE）。

## 時區與重複打卡

- 可於匯入介面選擇時區（預設為 `Asia/Taipei`）。未帶有時區資訊的時間將依此設定換算為 UTC 儲存。
- 匯入的打卡標示來源為「指紋匯入」（`source: 'import'`），只會新增，不會修改或刪除既有的打卡（員工的線上打卡、先前匯入的記錄都保留）。
- 同一位員工、同一個動作、同一分鐘已經有的打卡（不論來源），或同一個檔案裡重複的列，會自動略過並計入「重複略過」；同一個檔案再匯入一次不會多出任何記錄。
- 線上打卡與指紋記錄互補：計算工時、遲到早退與報表時不分來源，每一班簽到取最早、簽退取最晚。詳見 [attendance-sources.md](attendance-sources.md)。

## 員工對應機制

1. 匯入時會先依照 `USERID` 與 `NAME` 組合嘗試精確匹配員工。
2. 若組合匹配失敗，系統會嘗試單獨使用 `USERID` 比對員工編號、Email 及 `_id`。
   - 同一個員工編號有好幾位員工時（編號沒有唯一限制：離職後被沿用、同一個人重新到職另建一筆）：只有一位不是離職員工就用他；
     分不出來就不對應，列在 `missingUsers`（附 `reason`「這個員工編號有多位員工使用，請指定要對應的員工」），由管理者在畫面上指定。以前是後讀到的那一位蓋掉前面的。
3. 若 `USERID` 匹配失敗但有提供 `NAME`，且系統中僅有一位員工姓名符合，則會自動匹配該員工。
4. 若仍有無法對應的員工，API 會於回應的 `missingUsers` 欄位列出識別值、出現列號與樣本資料，前端可於對話框中選擇對應員工或標記忽略。
5. 完成映射後重新送出即可完成匯入，忽略的識別值將不會建立紀錄。

## API 路由

- `POST /api/attendance/import`
  - 需使用 `multipart/form-data`，欄位包含：
    - `file`：上傳之 Excel/CSV 檔案。
    - `mappings`：欄位對應設定（JSON）。
    - `options`：包含 `timezone` 與 `dryRun` 的設定（JSON）。
    - `userMappings`：重新對應使用者的設定（JSON，選填）。
    - `ignoreUsers`：欲忽略的識別值清單（JSON 陣列，選填）。
  - `dryRun: true` 時僅回傳預覽結果，不會寫入資料庫。

## 回應結構重點

- `preview`：檔案前 50 列的解析結果、錯誤與對應狀態（`ready`、`missing`、`ignored`、`error`，以及重複略過的 `duplicate`，附 `duplicateReason`）。
- `issues`：**所有**有問題的列（`error`、`missing`、`duplicate`；不含設定為忽略的），依列號排序，每一列的欄位和 `preview` 相同；最多 5,000 筆，超過時 `issuesTruncated: true`。`issueCount` 是有問題的列的總數。以前只有預覽的前 50 列看得到原因。
- 每一列的 `errors` 用畫面上的欄位名稱並附上檔案裡的原文：`缺少員工編號`、`打卡時間格式不支援：「三月五日」`、`打卡時間的日期或時間超出範圍：「2026-02-30 08:00」`、`無法判斷打卡類型：「外出」（可用 I／O、上班簽到／下班簽退）`、`缺少打卡時間`、`缺少打卡類型`（以前是 `缺少 USERID`、`無法解析 CHECKTIME：CHECKTIME 格式不支援`、`無法判斷 CHECKTYPE`）。`timestampError` 同樣改成「打卡時間…」。
- `missingUsers`：需人工映射或忽略的識別值清單。
- `summary`：包含總筆數、已就緒筆數（已對應到員工，含重複略過）、缺少對應筆數、忽略筆數、錯誤筆數、重複略過筆數（`duplicateCount`）與實際匯入筆數（`importedCount`）。
- 超過一批（500 筆）的檔案在中途寫入失敗：HTTP 500「考勤資料寫入失敗：已新增 N 筆，其餘尚未匯入；請稍後用同一個檔案再匯入一次（已有的打卡會自動略過）」，`summary.importedCount` 是已經寫入的筆數（以前回 400「無法讀取匯入檔案」）。
- 比對既有打卡：一批裡員工多、時間又分散（檔案沒有依時間或員工排序）時改成只查每一列自己那一分鐘；5 萬筆亂序的檔案匯入約 8 秒、重複匯入約 4 秒（以前 33 秒、56 秒）。
- 全部資料都與既有打卡重複時回傳 HTTP 200 與「沒有新的打卡記錄：N 筆與既有打卡記錄重複，已略過」，不視為錯誤。

若需要建立匯入範例，可使用下列最小範本：

```csv
USERID,CHECKTIME,CHECKTYPE,REMARK
A001,2024-01-05 08:00:00,I,早班
A001,2024-01-05 17:30:00,O,下班
```

或使用新格式範本：

```csv
編號,姓名,日期時間,簽到/退
D0021,楊世任,2025/11/1 上午 07:54:21,上班簽到
D0021,楊世任,2025/11/1 下午 12:00:03,下班簽退
```

將此檔案與對應欄位設定上傳，即可測試整體流程。
